# 维护与检查

README.md 是资源清单的唯一维护入口。不另外维护一份容易失去同步的 JSON 清单，也不复制上游源码。

## 本地检查

需要 Python 3.10 或更新版本，只有标准库依赖。在仓库根目录执行：

```sh
python3 -B scripts/check_catalog.py
python3 -B scripts/check_catalog.py --json
python3 -B -m unittest discover -s tests -v
```

返回码：`0` 为离线检查通过，`1` 为发现清单问题，`2` 为无法读取或解析输入。

脚本检查 catalog 标记区间、一级资源条目的统一格式、六种允许类型、重复 URL、空分类、重复显式锚点，以及 README 中的本地文件和显式锚点链接。它会忽略 fenced code block 中的示例。统计包括商业资源和相关清单，不应把总条目数写成“开源项目数”。

资源 URL 要求 HTTPS。GitHub 仓库名按不区分大小写去重，但 GitHub 内部文件路径保留大小写。目录使用 `<a id="stable-name"></a>` 的显式锚点，避免中文标题更改导致链接失效。

这是为本仓库约定格式编写的检查器，不是通用 Markdown 解析器；新增链接不要使用脚本不支持的嵌套括号和引用式写法。它只检查 README 的链接，不递归检查所有文档。

## 外部链接与内容复核

脚本不发起网络请求，不接触任何真实车辆，也不收集凭据。外部 HTTP 状态、页面内容、许可证、归档状态和产品能力需要人工复核。

遇到重定向时确认是否由原维护方迁移，再替换成新地址。遇到 403、429 或超时先记录访问限制，不自动判死链。检查通过只能说明文档结构有效，不能说明上游仍受维护或适合量产。

更新来源说明时记录实际查阅日期。不要只修改日期而不重新检查，也不要把网页可访问写成代码已测试。

## 自动化范围

首版只提供可手动运行的本地检查器及其测试，没有创建定时任务、GitHub Actions 工作流、Stars 抓取器或上游镜像。后续若增加 CI，可在 push / pull_request 时运行上述离线命令，避免每小时或每日无差别扫描。

当前版本的验证记录见 [validation.json](validation.json)，测试原始输出见 [unit-tests.txt](unit-tests.txt)。记录应明确区分本地检查、远端提交回读和 GitHub Actions 结果。
