# 维护说明

README.md 是资源条目的唯一维护入口。英文页负责导航，导读解释常见问题，审阅记录保存来源和变更理由；不维护第二份完整清单，也不复制上游源码。

## 本地检查

需要 Python 3.10 或更新版本，无第三方依赖。

```sh
python3 -B scripts/check_catalog.py
python3 -B scripts/check_catalog.py --json
python3 -B -m unittest discover -s tests -v
```

检查器验证条目格式、六种标签、重复 URL、空分类、目录锚点和 README 的本地链接。GitHub 仓库名按不区分大小写去重，文件路径保留大小写。返回码为：0 通过，1 发现问题，2 无法读取或解析。

新增的传播文件测试检查中英文导航、导读和署名页中的本地链接、既有锚点、首页统计、代码许可副本以及 Topics 待应用值。测试不访问外部网站，也不评估 SEO 排名或 AI 引用效果。

这套检查针对本仓库约定格式，不是通用 Markdown 解析器。CITATION.cff 的结构测试只核对必要文本字段；本轮另外用已安装的 YAML 解析器读取过文件，未运行完整 CFF 官方 schema 校验，也未验收 GitHub 的引用按钮。统计总数包含商业产品、标准、文档和相关清单，不能称作“开源项目数”。

本次结果见 [validation.json](validation.json)，原始测试输出见 [unit-tests.txt](unit-tests.txt)。历史记录保留在 Git 提交中。

## 查漏补缺

复查时按工程问题检查，不只搜索带有 SDV 标签的 GitHub 仓库。

| 方向 | 应同时考虑的资源 |
| --- | --- |
| 语言与运行时 | C/C++、Rust，裸机、RTOS、车载 Linux，商业工具链与安全材料 |
| 通信 | SOME/IP、DDS、IPC、信号模型，总线接口、分析与性能测试工具 |
| 国内工具与基础软件 | 总线分析、诊断标定、AUTOSAR、模型开发和测试自动化；区分公司、产品及开源子项目 |
| 开发与验证 | 需求与架构、模型与代码生成、虚拟 ECU、SIL/HIL、调试、覆盖率、静态分析和时序 |
| 生命周期 | 安全启动、密钥、OTA、软件物料清单、漏洞与发布管理、适用标准 |

这是人工审阅问题集，不要求每轮每格增加若干条。优先补用途明确、能够取得文档或交付物的资源；硬件接口与软件选件多时，提供产品入口而非逐个罗列型号。

## 来源和状态

优先阅读项目维护者、厂商、标准组织的资料。其他 Awesome Lists 用于发现线索，不证明项目仍活跃。链接迁移后核对维护方；访问失败记录 HTTP 状态或限制，不自动删除。

描述只承载上游能够支持的功能。保留影响采用的许可和架构差异，删除各条重复的套话。通用嵌入式项目不默认支持所有车规芯片，工具资格鉴定不扩大为整车认证。

编辑日期、资源复核日期和程序执行日期分开记录。本轮保留上一轮资源说明，仅调整阅读与传播资料，不把今天的日期写成逐个上游重新审计。
